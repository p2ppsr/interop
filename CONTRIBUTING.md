# Participation and contributions

All implementers may participate on the same terms. Artifact submissions identify a program and profile, an immutable artifact manifest, supported platforms, dependency closure, replay and retention rights, and an adapter implementing the [common lifecycle](adapters/README.md). Proprietary SUTs have the same admission requirements and appeal access as other implementations; source disclosure is optional.

## Technical proposals

Normative changes precede evaluations that rely on them. Each executable vector identifies a pinned specification clause or laboratory requirement, independent expected outcome, applicability, setup and teardown, raw evidence, and deterministic comparison rule. Independent validation requires an oracle beyond agreement between two copies of the same library.

Pull requests identify changes to semantics, vectors, infrastructure, or presentation. Relevant checks are `npm test`, `npm run check`, and the Python packaging tests in [the operator guide](docs/operator-quickstart.md). Contributions follow the editorial standard in [AGENTS.md](AGENTS.md).

## Rights and acceptance

Original contributions follow [LICENSE.md](LICENSE.md) and the [contribution agreement and IP pledge](legal/CONTRIBUTION-IP-PLEDGE.md). Admission to the normative corpus requires a traceable acceptance record identifying the rights holder, representative authority, agreement version and digest, contribution digests, effective date, disclosed third-party material, and legally effective assent. A Git author identity or Signed-off-by line alone is insufficient acceptance of the pledge.

SUT submissions use the separate [artifact agreement](legal/ARTIFACT-SUBMISSION-AGREEMENT.md). Their acceptance schedules identify the canonical artifacts, retention and access terms, dependencies, and lawful replay entitlements. Acceptance records preserve the applicable agreements and incorporated governance provisions by version and digest.

Repository contributions use synthetic data. Production credentials, real user records, and binaries lacking redistribution permission are excluded.

## Reports and disputes

Laboratory implementation defects follow [SECURITY.md](SECURITY.md). Ordinary interoperability discrepancies use repository issues with synthetic fixtures and the relevant requirement and evidence identifiers. Result disputes follow the [governance appeals process](GOVERNANCE.md#changes-disputes-and-appeals).
