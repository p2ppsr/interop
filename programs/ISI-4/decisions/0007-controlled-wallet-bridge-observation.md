# ISI-4 decision 0007 — controlled wallet bridge observation

Recorded 2026-09-21 by the founding steward.

The Android ITCVE may terminate the unchanged wallet's existing diagnostic request to `https://usercom.babbage.systems/signals` within its isolated network. It returns an HTTP success to the application's ordinary endpoint and retains only the event name and a fixed whitelist of wallet-bridge method, status, duration, queue, prompt, and response-freshness fields. Account identifiers, session identifiers, request arguments, error messages, and raw diagnostic payloads are excluded from the laboratory record. Other undeclared egress remains blocked. This observation boundary is diagnostic infrastructure; it creates no conformance exemption and does not change the wallet artifact or the published vector predicates.

Two clean Android trials of Metanet Explorer 1.1.10, [35573872562](https://github.com/p2ppsr/interop/actions/runs/35573872562) and [35575264398](https://github.com/p2ppsr/interop/actions/runs/35575264398), installed the exact admitted AAB derivative and configured the controlled WAB and Wallet Storage origins through the normal setup UI. Each trial initialized an account, admitted one `tm_users` UMP record, paid 1,000 satoshis from the WAB faucet descended from the verified Teranode-mined output, and recorded an accepted transaction with a seven-satoshi ToDo token output. The task creation dialog remained open in both trials. Neither met the task-visibility, reload, or redemption assertions.

An accepted transaction alone cannot establish application completion or spendability. Live WebView inspection during the second trial captured the React Native wallet response timeout. A third clean trial, [35576979224](https://github.com/p2ppsr/interop/actions/runs/35576979224), reproduced activation, mined-output funding, UMP publication, and the accepted seven-satoshi ToDo output. Its bounded wallet telemetry recorded the `createAction` prompt decision and activity posting, but no operation completion or WebView response before the application's timeout. This establishes a pending native call at the observation boundary, without establishing its cause.

The next qualification records only the wallet-storage JSON-RPC method, HTTP status, completion, and duration for each request to the isolated controlled storage service. Request arguments and response bodies are discarded. A separately executed offline oracle checks the mined-output proof, the accepted funding/UMP/ToDo transaction ancestry and digests, and the `tm_users` admission independently of application completion. The complete V001 discovery assertion and V002–V004 application assertions remain subject to their existing criteria in [decision 0006](0006-controlled-wab-discovery-and-funding.md). Historical trials and their failed workflow status remain intact.
