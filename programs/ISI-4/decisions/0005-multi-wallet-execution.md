# ISI-4 decision 0005 — multi-wallet execution and Android lane

Recorded 2026-09-20 by the founding steward.

ISI-4 admits wallet-specific drivers behind one evidence contract. Each driver uses the SUT's ordinary release installation, initialization and application boundary. The laboratory may route fixed production service identities to isolated fixtures or select supported endpoint settings, provided the artifact bytes, intervention and resulting service coverage are recorded. A driver reports every vector as `PASS`, `FAIL`, `BLOCKED`, `INCONCLUSIVE` or `NOT_APPLICABLE`; an unsupported prerequisite remains a result and does not erase the run.

V001 through V006 are executable for drivers that implement their declared observations. V007 remains blocked until the ISI-3 multi-remote storage profile can replace a storage counterpart and compare canonical state. V008 remains blocked until every applicable BRC-100 method and specified error has a clause-level fixture and independent predicate. A wallet may therefore receive a complete eight-vector report while the program still identifies blocked coverage.

The first admitted browser-extension driver evaluates Yours Wallet 5.1.0 with the pinned ToDo webroot. It provides fresh wallet state, controlled Wallet Storage, mainnet-format fixture funding, header/proof validation, transaction submission schedules, Chromium UI decisions, raw transaction evidence, PushDrop decoding, basket projections, cold reload, redemption and a safe BRC-100 method corpus. Two clean repetitions produced the same semantic projection: V001–V004 passed, V005–V006 failed, and V007–V008 were blocked. The outcome is an experimental result, not certification.

Android execution uses two equivalent capacity classes: a locally reproducible AVD on an admitted host and a repository-scoped KVM runner scheduled by GitHub Actions on Evans Creek infrastructure. The owned runner uses the digest-pinned Network Ops Android image, a non-root pod, a tokenless Kubernetes service account, direct allocation of the KVM device, and labels `tpnil-android-qa`, `android-emulator` and `kvm`. Plans, artifact digests, device properties and evidence remain repository-defined, so another qualified operator can execute them without depending on Evans Creek.

Metanet Explorer 1.1.10 is admitted by its exact publisher AAB. A universal APK derived by bundletool with the public laboratory key preserves the AAB payload for emulator execution while changing signer identity; signer-dependent behavior is outside that run. The app installed and launched, and its browser loaded the canonical ToDo artifact. Ordinary wallet activation stopped at phone-number verification, so V001 records the successful artifact/runtime assertions and the activation prerequisite as `BLOCKED`; dependent vectors are also `BLOCKED`.

BSV Browser 1.6.1 has no publisher binary attached to its public release history. The source-pinned laboratory build installed on the clean Android fixture, completed its ordinary local-wallet creation, exposed 28 BRC-100 methods to the live ToDo application, reported an authenticated mainnet wallet and reached transaction construction. The unfunded candidate then reported that 25 satoshis were required. This qualifies the engineering path without identifying the build as the production SUT; all vectors remain blocked until a canonical publisher binary is supplied and admitted, with controlled funding required for the transaction vectors.
