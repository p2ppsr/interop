# BRC-100 public boundary corpus 1.0.0

This prospective engineering profile calls all 28 wallet methods through an actual wallet's public API, with 42 independently scored predicates. Thirteen deliberately invalid requests exercise rejection behavior. The reference driver uses the pinned Toolbox wallet against real authenticated TypeScript or Go storage; the integrated native driver calls the unchanged Yours extension through `window.CWI`.

The profile executes signed transactions, staged signing and abort, basket and label metadata, BRC-29 incoming funds, encryption, independently verified signatures and linkage proofs, certificate acquisition and selective disclosure, actual Identity Services publication/discovery, and removal. Mined funding is the retained Teranode fixture; no synthetic transaction is accepted as native funding. Identity Services run in the actual Overlay engine with Mongo and signed SLAP advertisement. The reference wallet trusts the fixture issuer through its public settings-token API. The unchanged native wallet tests exclusion of that untrusted issuer; this is a negative trust check and does not qualify positive trusted native discovery.

`profile.json` freezes every assertion ID and method. `coverage.json` maps all source sections, typedefs, method contracts and wire-format sections in the exact pinned BRC-100 document to explicit partial or unexecuted coverage. Its source locators are laboratory identifiers because the standard does not number every clause. Executing all methods does **not** establish every validation limit, permission decision, ABI encoding, referenced-standard requirement, or full BRC-100 conformance. Those omissions remain visible in the coverage artifact.

Run `node scripts/run-wallet-boundary.mjs OUTPUT typescript` or `go`, then `node scripts/verify-wallet-boundary.mjs OUTPUT`. Prepare the declared Go compatibility build first. The native verifier accepts the integrated evidence directory with `--integrated` and independently recomputes successful and failed observations. Native failures remain findings; invalid-request timeouts, network failures and unsupported methods cannot qualify as correct rejection. An independently changed returned height must fail verification even if the original assertion remains PASS.

Retirement boundary: all listeners, temporary SQLite state and the local Mongo process are removed after each standalone run. The prospective native profile closes its extra listeners and clients inside the existing isolated container; container teardown remains the outer resource boundary. Historical wallet profiles and evidence retain their original component admission rules.
